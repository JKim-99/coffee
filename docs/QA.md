### QA-01 · P1 · 모바일 메뉴가 열리지 않음 [브라우저 재현 + 코드 확인]

- 재현: 모바일 메뉴 버튼이 보이는 홈에서 ‘메뉴 열기’를 한 번 누른다.
- 실제: 클릭 전후 모두 접근성 트리에 `collapsed / 메뉴 열기`로 남고 주 메뉴 링크가 나타나지 않는다.
- 기대: 한 번 누르면 메뉴가 열리고 `aria-expanded="true"`가 되어 메뉴·문의·로그인에 접근할 수 있어야 한다.
- 원인: `index.html:14,16`에서 함께 로드되는 `app.js:19-26`과 `site-auth.js:7-14`가 같은 버튼에 각각 토글 핸들러를 등록한다. 첫 핸들러가 연 상태를 두 번째가 닫는다. `styles.css:11`은 680px 이하에서 내비게이션을 기본 숨김 처리한다.
- 개선: 공통 내비게이션 이벤트 등록을 한 파일로 통합한다.
- 재검증: 375px·680px에서 클릭/Enter/Space로 열기·닫기, 681px 이상에서 일반 링크 접근을 확인한다. 두 스크립트를 함께 로드하는 통합 테스트를 추가한다.

### QA-02 · P2 · 로그인 후 선택한 관심 메뉴를 이어서 저장할 수 없음 [이동 재현 + 코드 확인]

- 재현: 비회원이 추천 카드 하트를 누른다. 경고를 닫으면 `login?next=%2F`로 이동한다(직접 확인).
- 실제: `favorites.js:34-37`은 현재 경로만 전달하고 메뉴 ID나 저장 의도·스크롤 위치는 보존하지 않는다. `auth.js:103`은 `next`를 읽지 않고 항상 홈으로 이동한다. 홈 추천은 다시 무작위로 생성되므로 선택한 카드를 찾기 어려울 수 있다.
- 기대: 로그인 필요성을 먼저 안내하고, 로그인 후 원래 메뉴에서 저장을 이어갈 수 있어야 한다.
- 개선: 안전한 내부 복귀 주소와 선택 메뉴 ID를 보존하고, 로그인 후 해당 상세 화면 또는 저장 확인 단계로 연결한다. 자동 저장 정책을 정해 사용자에게 알린다.
- 재검증: 비회원 하트 → 로그인 → 동일 메뉴 확인·저장. 실제 로그인 완료는 이번 점검에서 실행하지 않았다.

### QA-05 · P2 · 추천 카드 이미지에는 실패 대체 처리가 연결되지 않음 [코드 확인]

- 재검증: QA-01 수정 후 비회원/회원 각각에서 상단·본문·푸터 진입을 비교한다. 실제 문의 제출은 하지 않았다.

### QA-07 · P2 · JavaScript 실패 시 주요 콘텐츠와 문의 유도가 사라짐 [코드 확인]

- 조건: `app.js` 로딩 실패 또는 JavaScript 비활성화.
- 실제: `index.html:63`의 추천 영역은 빈 컨테이너다. `index.html:59,67`의 `reveal` 영역은 `styles.css:5`에서 투명하게 시작하고 스크립트가 있어야 표시된다(모션 감소 설정에서는 예외). `noscript` 안내도 없다.
- 영향: 추천이 비어 있고 제목·전체 메뉴 링크·본문 문의 버튼이 시각적으로 숨겨져 첫 방문자가 이유를 알기 어렵다. 상단 메뉴와 히어로 메뉴 링크 등 일부 탐색은 남는다.
- 개선: 기본 콘텐츠를 보이게 하고 스크립트 실행 시 애니메이션을 적용한다. 정적 추천/전체 메뉴 대체 링크와 실패 안내를 제공한다.
- 재검증: app.js 차단 및 JS 비활성화 환경에서 핵심 탐색이 가능한지 확인한다.

### QA-08 · P2 · 비공식 시안임을 첫 화면에서 알기 어려움 [개선 제안]

- 근거: `index.html:7-10`의 제목/설명은 브랜드명뿐이고, 비공식 시안 설명은 `index.html:81`의 푸터에 있다. 브랜드와 실제 상담 전화가 함께 제공된다.
- 영향: 처음 방문한 사람이 공식 서비스로 이해한 채 로그인하거나 문의 화면으로 이동할 수 있다.
- 개선: 첫 화면에 ‘비공식 소개 시안’ 안내를 명확히 표시하고 계정·문의 서비스 운영 주체와 공식 사이트 연결을 알린다.
- 확인 기준: 스크롤 없이 사이트 성격을 이해할 수 있는지 신규 사용자에게 확인한다. 법적 위반 여부에 대한 판단은 아니다.

### QA-09 · P3 · 메뉴를 고르는 데 필요한 정보가 부족함 [개선 제안]

- 근거: `app.js:54-61`의 추천 카드는 사진·분류·이름만 제공한다. 상세에서는 영양 정보를 볼 수 있지만 가격은 없고 카드에서 카페인·알레르기 관련 구분을 바로 할 수 없다.
- 영향: 처음 온 사용자는 각 상세 화면을 반복해서 열거나 공식 사이트로 이동해야 한다.
- 개선: 확인 가능한 출처와 갱신 기준이 있는 가격·카페인 등의 정보를 추가하고, 정보가 없으면 그 사실을 명확히 안내한다. 확인되지 않은 제품 정보를 추정해 표시하지 않는다.
- 확인 기준: 사용자가 원하는 음료를 고르는 데 필요한 상세 이동 횟수와 정보 이해도를 비교한다.

### QA-10 · P3 · 모바일 보조 글씨가 매우 작음 [CSS 확인, 실기기 가독성 미검증]

- 근거: `styles.css:11`에서 카드 분류 7px, 전체 메뉴 링크 9px, 푸터 안내 9px로 지정한다.
- 영향: 메뉴 분류와 비공식 시안 안내를 읽으려면 확대가 필요할 수 있다.
- 개선: 보조 텍스트 크기와 대비를 높이고 긴 메뉴명·200% 확대 상황을 함께 점검한다.
- 확인 기준: 320px·375px·680px, 확대 200%, 실기기에서 잘림과 읽기 부담을 확인한다. 이번 결과만으로 접근성 표준 위반을 단정하지 않는다.
