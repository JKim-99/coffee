## 1. 관리자 페이지 생성

### 목표

관리자가 로그인해 문의를 관리하고, 사이트 관리 기능을 안전하게 사용할 수 있는 관리자 페이지를 만든다.

### 작업 계획

- [x] 일반 회원 세션과 분리된 관리자 로그인 기준을 설계한다. 관리자 secret을 사용하며 `cf-access-authenticated-user-email` 같은 위조 가능한 요청 헤더만으로 권한을 주지 않는다.
- [x] Pages Function에서 관리자 전용 세션 쿠키를 검증하는 공통 인증 경계를 구현한다.
- [x] 관리자 페이지 HTML/CSS/JS를 추가하고 인증이 없으면 관리자 로그인을 요구한다.
- [x] 문의 목록·상세(제목, 유형, 이메일, 작성 시각, 답변 상태)를 제공한다.
- [x] D1에 답변 내용/시각 및 메일 발송 상태를 저장하는 migration과 답변 저장 API를 구현한다.
- [x] 관리자 API는 목록·답변 작성 전 구간에서 서버 측 관리자 권한을 검증한다.
- [x] 로컬 D1/Pages Functions에서 관리자 권한 및 답변 API를 검증한다.
- [ ] Cloudflare Dashboard에서 강한 `ADMIN_PASSWORD`를 Production secret으로 직접 설정한 뒤 Production 관리자 로그인을 확인한다. Secret은 채팅/코드에 기록하지 않는다.
- [ ] 발신 도메인/Email Sending 권한을 준비하고 `EMAIL` binding 및 `EMAIL_FROM`을 설정한 뒤 실제 답변 알림 이메일을 수신 테스트한다.

### 완료 조건

- 비관리자 사용자는 UI를 직접 열거나 API를 호출해도 관리자 데이터에 접근할 수 없다.
- 관리자만 문의 목록/상세를 열람하고 허용된 관리 작업을 수행할 수 있다.
- 로그아웃·세션 만료 후 관리자 API가 접근을 거부한다.
- 기존 회원/문의 데이터가 migration 후 보존된다.

## 2. 선호 메뉴 지정

### 목표

로그인 사용자가 메뉴를 선호 메뉴로 등록/해제하고, 본인의 선호 목록을 다시 확인할 수 있게 한다.

### 작업 계획

- [ ] 선호 데이터를 어느 범위로 저장할지 결정한다. 권장: `user_id`와 안정적인 menu `id`를 저장하는 별도 `favorite_menus` 테이블.
- [ ] 사용자당 메뉴 중복 저장을 막는 복합 UNIQUE 제약 및 생성 시각 컬럼을 D1 migration으로 추가한다.
- [ ] 세션 사용자만 접근 가능한 선호 메뉴 API를 구현한다. 다른 사용자의 선호 데이터는 조회·변경할 수 없어야 한다.
- [ ] 메뉴 카드/상세 화면에 선호 등록·해제 UI를 추가한다.
- [ ] 회원 정보 또는 별도 “선호 메뉴” 화면에서 등록한 메뉴를 확인하고 상세 페이지로 이동할 수 있게 한다.
- [ ] 로그인하지 않은 경우 로그인 안내를 제공하고, 로그아웃/세션 만료 시 API가 401을 반환하는지 검증한다.
- [ ] 메뉴 ID 유효성, 중복 클릭, 메뉴 목록 변경/삭제 상황을 테스트한다.

### 완료 조건

- 사용자가 선호 메뉴를 추가/해제한 결과가 D1에 저장된다.
- 중복 선호가 생성되지 않고 각 사용자의 데이터가 서로 분리된다.
- 새로고침/다른 페이지 이동 후에도 로그인 사용자의 선호 상태가 유지된다.
- 접근 제어 및 D1 migration 테스트를 통과한다.
